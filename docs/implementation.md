# Implementation notes

## Структура страницы

`index.html` — одна статическая страница с якорными секциями:

1. header и mobile navigation;
2. hero с главным CTA;
3. portfolio/projects;
4. concrete advantages;
5. work process;
6. lead form;
7. materials;
8. trust block;
9. FAQ на native `<details>`;
10. final CTA;
11. footer.

## CSS-архитектура

`css/styles.css` построен вокруг:

- CSS custom properties для палитры, типографики, радиусов и ширины контейнера;
- `.shell` для единой горизонтальной границы;
- секционных блоков и компонентных классов (`.project-card`, `.process-step`, `.material-card`, `.trust-card`);
- CSS Grid для основных раскладок и Flexbox для навигации и CTA;
- медиазапросов для 1120, 920, 760, 520 и 360 px;
- `prefers-reduced-motion: reduce` для отключения заметных переходов.

Фотографические demo-материалы лежат в `assets/images/photos` как локальные JPEG-файлы. Hero использует единственную пометку `фото-референс`, а секция проектов — общий текст о демонстрационных направлениях, чтобы реальные интерьерные снимки не воспринимались как выполненные объекты FORMA. Прежние SVG-визуализации сохранены в `assets/images` как неиспользуемый fallback. Источники и лицензионные замечания вынесены в `docs/assets-sources.md`.

Для каждого крупного изображения задан отдельный `object-position`, а поверх фото добавлен мягкий градиентный слой. Это помогает сохранить editorial-композицию текущего сайта и контролировать crop без добавления JS или сторонних библиотек.

## JavaScript

`js/main.js` не зависит от библиотек и отвечает за:

- открытие/закрытие мобильного меню, `aria-expanded`, Escape и закрытие по клику вне меню;
- состояние шапки при прокрутке;
- появление секций через `IntersectionObserver`;
- текущий пункт навигации через `aria-current`;
- переход к форме с выбором способа связи;
- локальную валидацию lead form;
- demo success state без `fetch`, отправки на сервер или сохранения данных;
- восстановление формы через «Заполнить ещё раз».

## Responsive-подход

- desktop: две колонки hero, крупная portfolio-сетка, шесть process-карточек в три колонки;
- tablet: уплотнённая сетка, две колонки материалов и процесс в две колонки;
- mobile: полноценная одноколоночная композиция, раскрывающееся меню, удобные radio-кнопки и вертикальная форма;
- малые экраны 320–360 px: уменьшенные заголовки, CTA на всю ширину и сохранённые отступы.

## Форма и будущая интеграция

Сейчас форма работает только в браузере. Она уже разделяет вводные по именам полей и имеет понятную точку подключения:

- заменить `event.preventDefault()` в обработчике `submit` на согласованный `fetch`, Tilda Forms или webhook;
- сохранить текущие имена полей либо сопоставить их с полями интеграции;
- оставить клиентскую проверку перед отправкой;
- после подключения добавить серверную валидацию, обработку согласия и реальную страницу/состояние успеха.

## Ограничения текущего этапа

Реальные контакты, фото проектов, цены, сроки, юридические данные, поставщики и условия гарантии не заданы исходным брифом, поэтому в интерфейсе используются placeholders, фото-референсы и нейтральные формулировки. Перенос в Tilda отдельно не проектировался и не выполнялся.
